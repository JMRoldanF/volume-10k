# GenApp volume corpus — 10k programs

Synthetic COBOL/CICS/Db2 estate for stress-testing COBOL analysis, explanation
and call-graph tooling. Generated by `genapp/tools/genvol/genvol.py`; see that
directory's README for the generator and its options.

This is **not** runnable code. It is fixed-format source meant to be *read* by
tools: realistic structure, but no compile or bind step and no z/OS dependency.
The COBOL stops at column 72. The BMS mapsets are HLASM and do not — see below.

## Ground truth

`manifest.json` holds the exact expected graph, so tool output can be scored
rather than eyeballed:

- 28,574 call-graph edges — 25,216 resolvable from literals, 3,358 requiring
  dataflow (`LINK PROGRAM(WS-VAR)`, `CALL` from an `OCCURS` dispatch table) or a
  cross-reference against `cntl/csdvol.txt` (`START TRANSID`)
- Every edge carries its target, kind, and **the source line of the verb**
- 60 injected recursion rings (59 strongly connected components in the
  emitted source), 6 hubs (fan-in 760–823), max call depth 32
- 1,234 entry points, 1,096 true orphans (drivers with a TRANSID and JCL jobs
  are excluded — they are entry points by design, not dead code)
- Per-program dead paragraphs, copybook fan-in (`ZKCOMMON` is copied 8,722×)

Score with:

```python
import json
truth = json.load(open("manifest.json"))
expected = {(p["name"], c["target"])
            for p in truth["programs"] for c in p["calls"]}
print("recall   ", len(actual & expected) / len(expected))
print("precision", len(actual & expected) / len(actual))
```

## Context window

Every program fits a **200,000-token** window — see `window_cap` in the
manifest. The corpus was generated with `--fit-window`, so it contains **no
over-window program**: the largest file is 12,076 lines (~545 KB, 94% of the
budget). Regenerate without that flag to get the over-window cases back once a
fallback path exists.

The budget assumes **3.4 characters per token**, which is a placeholder, not a
measured value. Measure it on this corpus with `count_tokens` before relying on
the cap.

## BMS

Mapsets are HLASM, whose fixed format is **not** COBOL's: columns 1–71 hold the
statement, column 72 is the continuation indicator — **any** non-blank character
continues — and columns 73–80 are a sequence area the assembler ignores. A
continued statement resumes in column 16.

The 105 bulk mapsets are all valid BMS and all differ. A template repeated
105 times measures a parser against the template, not against BMS, so what
varies is what a template never moves. `injected.bms_variation` reports the mix
**as generated**, per feature, in files — a feature missing there is coverage
this corpus does not have:

| | |
|---|---|
| column 72 | mostly `X`, some `*`, a few `C` `Y` `-` `1` |
| columns 73–80 | absent, present throughout, or on a subset of records within one file |
| continuation | resuming in column 16, or later — but only inside a quoted literal, where columns 16..71 are content and the leading blanks belong to the string |
| column 71 | literals filled hard against the marker, so column 71 holds real content and nothing separates it from column 72 |
| comments | `*` banners in column 1 |
| remarks | after the operands of a plain statement, and after the trailing comma of a **continued** one |
| literals | upper and mixed case. Lower case inside a literal is real and frequent; outside one it would be invalid |
| statements | `TERM=3270-2`, `TYPE=FINAL` with and without a name, `PRINT NOGEN`, `EJECT`, `SPACE n`, `TITLE` with a name, blank records |

Six labelled hazards sit alongside them, each under its own key in `injected`:

| file | hazard |
|---|---|
| `ZZMNEMON.bms` | fields named `TITLE`, `START`, `END`, `COPY`, `EQU`, `USING`, `SPACE`, `PRINT` — all valid in the name field (column 1), all mis-read by a lexer matching keywords by token rather than by column position |
| `ZZAMPERS.bms` | `&SYSPARM` is a **variable symbol** (one ampersand); `&&` escapes a literal ampersand and *only* inside a quoted string, so `INITIAL='PROFIT && LOSS ACCOUNT'` renders one |
| `ZZLITRAL.bms` | literals where the record boundary is content: one spanning **three** records, one resuming in column 17 so column 16 is a blank inside the string, one stopping short of column 71 so the padding is in the string |
| `ZZDIRECT.bms` | HLASM statements around the BMS macros — `TITLE` with a name, `PRINT NOGEN`, `EJECT`, `SPACE 2`, `COPY`, `EQU` against `*`, `X'40'` and `*+4`, `TERM=3270-2` |
| `ZZSTDAT.bms` | the member `ZZDIRECT` copies. `STDBRT EQU ATTRBRT` resolves only by following the `COPY` |
| `ZZDAMAGE.bms` | **not valid HLASM**, on purpose, and the only file here that is not: a `0x1A` transfer EOF mark, tabs where blanks belong, a blank record straight after a column-72 marker, and a continuation resuming outside a literal |

`injected.bms_literal_expected` carries the exact string HLASM assembles for
each field of `ZZLITRAL.bms`. Score against those: every case in that file fails
**silently**, producing a shorter or longer literal without raising anything, so
the reassembled value is the only thing separating a correct parser from a
plausible one.

If you script a measurement over these files, thread the quote state across
records. A per-record check walks into the ASCII-art banners and reports their
contents as remarks, and calls the closing record of every continued literal an
unterminated string.

## Deliberately hostile cases

Tagged in the manifest, one program each: 120-level `IF` nesting; `GO TO
DEPENDING ON` spaghetti; obsolete `ALTER ... TO PROCEED TO`; 300 outbound
`CALL`s; dispatch resolved from a table of names; the largest-file case; lower
case source with embedded tabs; `EXEC SQL PREPARE` from a host variable; a large
program with no callers; and the same `PROGRAM-ID` in two directories
(`src/MT/` and `src/attic/`).

## Regenerating

Output is deterministic for a given seed:

```sh
python3 ../genapp/tools/genvol/genvol.py \
  -n 10000 --boundary 12 --chains 40 --chain-depth 20 --cycles 60 \
  --fit-window --window-tokens 200000 --chars-per-token 3.4 \
  --seed 20260729 -o .
```
